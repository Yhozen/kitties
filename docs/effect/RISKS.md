# Risks

The risk register for the Effect rewrite. Each risk has a mitigation already built into
[PLAN.md](PLAN.md) and a trigger that tells us to act. Review it at the end of every phase and
record changes in the phase status table in [README.md](README.md).

Likelihood and impact are H (high), M (medium) or L (low).

| # | Risk | L | I | Mitigation | Trigger to act |
|---|---|---|---|---|---|
| R1 | **Alchemy v2 beta churn.** `alchemy/Workflows` first shipped in `2.0.0-beta.84` on 2026-10-24. Betas break often, and there is no guidance for in-flight runs across versions. | H | H | Exact pins. A bump only through a PR that re-runs the spike-1 suite. Workflow code uses `effect/workflow`, so the engine Layer can be swapped. `NativeEngine` is the fallback. | Spike 1 fails, or a fix we need lands only in a breaking release. |
| R2 | **Effect 4 minor churn.** 4.0 went GA on 2026-10-01 and 4.1 followed within a month. The Effect AI, SQL and test packages track Effect's version exactly. | M | M | Pin `effect@4.1.1` with a pnpm override so only one instance loads. Upgrade all `@effect/*` packages together. | Peer conflicts, or two Effect instances in one bundle. |
| R3 | **Workflow engine semantics.** Limits apply per run segment, not per activity. Sleeps of 60 s or less don't suspend. Runs park after 8 cut-offs and then retry hourly. Failed activities are journaled forever. Journal keys are `name/attempt`. Journals are never purged. | H | H | Design rules 2–4. A replay-every-step test helper. A run-health table with alerts. Child workflows bound segment length. A purge job in Phase 10. | Any spike-1 case behaves differently from [RESEARCH.md](RESEARCH.md). |
| R4 | **Boat API changes and EU-only latency.** Boat runs only in the EU, gives a VM a new IP on every resume, and has quirks: labels are dropped on restore, and idempotency lasts 24 h. | M | M | Boat code stays in one module. KittyDO uses an EU `locationHint`. Namespace isolation keeps us clear of the Go stack. Every Boat call is an idempotent activity. | Contract tests against the live API fail. |
| R5 | **Outbound guest WebSocket fails.** No egress filtering has been seen, but a long-lived WSS from Boat to Cloudflare has never been tested. | L | H | Spike 3 tests reconnect across stop/resume. Plan B: the DO dials a private `POST /host` URL with mutual auth. | Spike 3 shows drops or blocked upgrades. |
| R6 | **Access and PWA on phones.** An installed PWA on iOS may not share the browser's Access cookie. Push actions can run after the Access session has expired. | M | M | Install test in Phase 3. A PWA-friendly Access session length. Push actions open the app behind Access, or carry a signed single-use 5-min token (Phase 8). | Phase 3 install test, or Phase 8 locked-phone test, fails. |
| R7 | **ChatGPT subscription admission or authorization fails.** The private Cloudflare deployment must pass live admission using its own dynamic registration. | M | L | Disabled until real next Responses admission. One-time Mac helper; encrypted shared credentials, fenced refresh and explicit pauses. No automatic paid fallback. | Live admission fails or the documented registration/serving policy changes. |
| R8 | **Cost and memory of streaming through a DO.** Frames keep the DO awake. Slow viewers can buffer inside a 128 MB isolate. | M | M | Stream only while viewers are connected. Per-viewer credit with drop-to-latest. Spike 4 decides on `KittyStreamDO`. Plan B is Cloudflare Realtime (WebRTC). Phase 10 cost report. | Spike 4 shows input-ack p95 regressions or memory growth. |
| R9 | **MCP mismatches.** Effect's `McpClient` speaks only protocols 2025-11-25 and 2026-07-28, takes static headers, and has no OAuth or retries. Some vendors restrict clients. | M | M | Spike 7 probes the target servers. A thin Streamable-HTTP client on `effect/http` is plan B. OAuth is our own layer (Phase 9). | Spike 7 shows a server that won't negotiate. |
| R10 | **agent-desktop on our guest.** It targets GNOME 46. Openbox and Xvfb are unverified, AT-SPI is not installed, and every call on Linux spawns a process. | M | L | Spike 6 probe. The Phase 7 A/B decides. Pixel tools stay. agent-browser covers web pages. | Spike 6 or the A/B fails. |
| R11 | **Immature Vitest 5 and Cloudflare test integration.** `vitest-pool-workers` 0.23 is Vitest 4 only, and `@cloudflare/vitest-plugin` has open issues. | M | L | Test DOs black-box through `alchemy dev`. Use the plugin only if spike 1 shows it can host Alchemy DOs. | Flaky or impossible DO tests. |
| R12 | **A long freeze of the Go product.** Go is frozen for roughly 13–15 weeks. | M | M | Live desktop first (D15). Fixes stay allowed on Go. Each phase leaves `next` usable. | The owner needs a feature before cutover. |
| R13 | **Losing the encryption key.** Losing the KEK makes encrypted data unreadable. | L | H | A Worker secret with an off-Cloudflare escrow copy. Envelopes carry a key id. Restoring from escrow is a drill step in Phase 10. | Any key rotation or stage rebuild. |
| R14 | **Bypass routes as an attack surface.** `/hooks/*`, `/guest/*` and the OAuth discovery paths skip Access. | M | H | Separate routers that cannot reach `/v1`. Signatures and timestamps. A 1 MB cap before verification. WAF rate limits. The guest principal is low-privilege. | Any unauthenticated request reaches an owner handler in tests. |
| R15 | **Effects replayed after a restore.** Point-in-time recovery is per DO, not consistent across DOs. | L | H | A `restoredEpoch` in HomeDO interrupts older runs for owner review instead of replaying them. Tokens rotate after a restore. | Any restore drill. |
| R16 | **Collisions with the Go stack on the shared Boat account.** | M | M | A separate deployment id and the `kn-` name prefixes. A same-name isolation test in Phase 6. | Any Go/next lifecycle error that names the other stack's VM. |
